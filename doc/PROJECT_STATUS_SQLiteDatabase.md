# 付録C. JSONL → SQLiteデータベース

## 目的

記事ビューア専用データベースを構築する。

SQLiteは検索性能ではなく、

記事表示を目的とする。

---

## 入力

```
ja_wiki.jsonl.bz2
```

---

## 出力

```
wikipedia_articles.sqlite3
```

---

## 保持内容

記事単位で保持する。

RAGのチャンクとは独立した構造とする。

Viewerでは記事全文を扱う。

---

## RAGとの役割分担

RAG

* チャンク単位
* 検索最適化

Viewer

* 記事単位
* 表示最適化

両者は目的が異なるため、

同一データ構造へ統合しない。

---

## 採用理由

RAGではチャンク分割やオーバーラップなど検索効率を優先する。

一方で記事表示では、

元記事を自然な形で閲覧できることが重要である。

そのため、表示用データベースを別に持つ設計とした。

---

## 将来拡張

SQLiteはViewer専用とする。

今後追加予定の

* 記事内検索
* 履歴
* HTML表示
* セクションジャンプ

などはSQLiteを利用して実装する。

RAG側からSQLiteを直接参照しない方針を維持する。
