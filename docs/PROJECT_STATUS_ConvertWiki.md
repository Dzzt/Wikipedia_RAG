# 付録A. Wikipediaダンプ → JSONL

## 目的

Wikipediaダンプから、RAGと記事ビューアの双方で利用できる中間データを作成する。

最終的な中間形式は **JSONL（bz2圧縮）** とする。

このJSONLを唯一の入力データとし、

* FAISSインデックス
* SQLiteデータベース

を生成する。

つまり、JSONLを「マスター形式」と位置付けている。

---

## JSONL形式を採用した理由

Wikipediaダンプを直接利用すると、

* XML解析が必要
* 再利用しづらい
* 各ツールごとにパーサを書く必要がある

そこで、一度JSONLへ変換しておけば、

* SQLite生成
* ベクトル生成
* デバッグ
* 内容確認

を共通フォーマットで行える。

---

## JSONLの形式

既に公開されている

```
ja_wiki.jsonl
```

と同じ形式を採用する。

この互換性を維持することを前提としている。

---

## 圧縮

JSONLは

```
bz2
```

圧縮したまま扱う。

理由

* サイズ削減
* ストリーム処理可能
* 展開不要

以降の処理も、可能な限りbz2のまま行う。

---

## この段階の成果物

```
ja_wiki.jsonl.bz2
```

これを以降すべての入力データとする。
